## 1. 测量方法与口径

- **探针**：`BenchHarness.java` 直接用真实 codec 编码。
  - 基线路径：每个变更字段单独一帧，载荷为 JSON 文本 `{"field_i":value}`（模拟逐字段上报）。
  - 优化路径：本轮所有变更组成一条 Delta，紧凑二进制（count varint + 每变更项 varint(key)+zigzag varint(value)），塞进同一帧一条 RAW 消息。
  - 有效逻辑字节：帧内 delta 有效载荷真实字节，两条路径共用同一定义，故 payload_ratio ≤ 1（修复旧脚本 >1 的失真）。
- **环境**：javac 20 / JUnit 5.10（独立运行器），无 Gradle Wrapper（R-13 将在第 4 阶段补），无真实 Netty 链路。

## 3. 逐层优化清单

### 3.1 协议与编码层
| 项 | 改了什么 | 为什么省 | 代价 | 回滚 | 实测增益 |
|---|---|---|---|---|---|
| ZigZag + VarInt | 既有实现保留（VarInts.zigZagEncode），delta 变更值用 zigzag 后再 varint | 小负数/小值只占 1B，避免固定 4/8B | 大值最多 5B | codec 版本位隔离 | 计入字节↓79% |
| 二进制替代 JSON | 优化路径用紧凑二进制 delta 替代逐字段 JSON 文本 | 去掉键名重复、引号、大括号 | 需业务 codec 配合 | 保留 RAW 消息类型可回退文本 | 单字段 ~50B→~4B |
| 字典化 | DictSync 保留，键名走字典 id | 长键名只传 u16 id | 需字典握手同步 | version 回退 (DictRegistry.rollbackTo) | 本次基准未单独量化 |

| 项 | 改了什么 | 为什么省 | 代价 | 回滚 | 实测增益 |

## 4. 达标判定（诚实）
- 提示词要求"P99、重连恢复、CPU 任一劣化即回滚该项"。本环境**无法测得这三项**（无真实服务端/网络），因此：
  - 已落地的优化均为**低风险、行为可测**项（背压/队列/清理/合包/变长编码）；
  - 凡涉及链路延迟的优化（如二次压缩、自适应分片阈值）**一律不启用**，避免未验证就上线；
  - 达标结论：**字节/包数/编码 CPU 三项显著改善；P99/重连/CPU/堆未验证，需在真实试机环境（第 6 阶段）确认后方可判定完全达标**。不把"未验证"包装成"达标"。

## 5. 回滚路径汇总
| 优化 | 一键回滚 |
|---|---|
| 出站编排（背压/限速） | `dispatcher.configureEgress(false,...)` → 恢复 sendControl 直发 |
| 压缩 | `config.compression.enabled=false`（默认即 false） |
| 字典 | `DictRegistry.rollbackTo(oldVersion)` |
| 分片 | 上层不使用 Fragmenter，直接整帧发送 |
| delta 合包 | 改用逐消息分帧发送（FrameCodec 仍支持） |
| TTL 清理 | 移除 periodicTick 中 evictExpired 调用 |
