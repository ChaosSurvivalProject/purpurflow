# 07 · 风险与回滚（第 5 阶段）

## 7.1 分层风险与回滚

| 层 | 升级兼容风险 | 失效表现 | 回滚方式 |
|---|---|---|---|
| L6 兼容探测 | 低 | 装 Mod 但探测失败 → 走 vanilla，功能缺失但不崩 | `canSend` 失败即降级 |
| L5 控制面 | 中（握手状态机复杂） | 握手失败 → 增强流关闭 | `handshake.timeout-ms` 调小 + `enabled=false` |
| L4 压缩 | 中（CPU/净收益不确定） | 压缩反而增大/CPU 高 | `compression.enabled=false`（默认） |
| L3 语义 | 中（幂等/去重边界） | 状态不同步 | 降为全量快照（关闭 delta） |
| L2 编码/字典 | 中（字典版本错配） | 解码乱码 | `dictionary-version` 回退上一版 |
| L1 帧层 | 低 | 分片重组失败 | 请求增量补发 / 全量快照 |
| L0 承载 | 极低（官方 API） | 通道不可用 | `enabled=false` |
| 可选 PacketEvents ② 层 | **高**（耦合 NMS/版本） | 拦截失效/版本不适配 | `optional.packetevents.enabled=false`（默认） |
| Netty 管线改造 | **高**（与 Purpur 耦合） | 升级易碎 | 不采用；如采用则一键关闭开关 |

## 7.2 升级兼容风险详述

- **协议版本**：`protocol-whitelist` 控制可接受版本；新版本 MC 需重新核实坐标与 API（01 文档流程）。
- **字典版本**：`dictionary-version` 与 `dictVer` 帧字段联动；双端字典版本对齐才可正常解码，不对齐走 `DICT_SYNC` 增量或回退。
- **1.21.11 → 26.1 迁移**：1.21.11 是最后混淆版本，未来用 Mojang mappings（本工程已采用），主要差异在映射名而非逻辑，升级成本已前置降低。
- **Purpur/Paper 升级**：只用官方 API（Messenger / plugin messaging），不碰 NMS，升级风险局限在 API 签名，白名单 + 编译期检查兜底。

## 7.3 一键回滚路径

1. **总开关**：`enabled=false` → 服务端不注册/不发送任何增强帧，客户端 `canSend` 探测失败 → 行为与原版完全一致。
2. **协议白名单**：收窄 `protocol-whitelist`，只保留当前验证通过的版本。
3. **字典版本回退**：`dictionary-version` 回退到上一稳定快照。
4. **可选层逐层关闭**：先关 `optional.packetevents`，再关 `compression`，再关 delta（退化为全量快照），最后 `enabled=false`。

每一层的失效表现均在 7.1 表中写明，关闭后不影响 vanilla 玩家。
