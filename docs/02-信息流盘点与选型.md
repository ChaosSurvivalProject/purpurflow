# 02 · 信息流盘点与选型（第 2.0 阶段）

> 用户未指定优化对象，因此第一步先做信息流盘点，再按收益/风险排序选型。本章是交付物第一章。

## 2.0.1 统一维度盘点表

维度：**方向 / 数据形态 / 频率与峰值 / 可否丢弃 / 可靠有序要求 / 优先级 / 当前字节量级**。
字节量级为【工程建议】估算基线，实际以压测（06 文档）实测为准。

|---|---|---|---|---|---|---|---|

## 2.0.2 收益/风险排序与选型结论

**排序原则**：优先「高频 × 高字节 × 可优化空间大 × 风险小」的子流。

| 排名 | 子流 | 收益 | 风险 | 是否纳入默认 |
|---|---|---|---|---|
| 1 | ④ 控制面 | 中（省包数、稳连接） | 极低 | ✅ 默认必做 |
| 2 | ① 玩家状态/UI 遥测（高频可丢弃） | **高**（合包 + 脏位图收益最大） | 低 | ✅ 默认必做 |
| 3 | ① 任务/经济/领地（可靠） | 中高（字典化 + delta 降字节） | 低 | ✅ 默认必做 |
| 4 | ③ 代理转发 | 低（只兼容不新增链路） | 低 | ✅ 仅兼容 |
| 5 | ② 原版同步包差量/过滤 | 高但需包级拦截 | **高**（耦合 NMS/PacketEvents） | ⛔ 默认关闭，可选层 |

### 【工程建议】默认选型

- **默认（L0–L5 全开，L4 压缩关）**：纯官方 API（Bukkit plugin messaging + Fabric Networking），优化对象为 **① + ④**。理由：收益最大、风险最小、完全贴合 H1。
- **可选增强层**：PacketEvents 用于 ② 原版同步包差量/包过滤，独立开关、默认关闭，需写明 1.21.11 适配风险（见 07 文档）。
- **不推荐默认改 Netty 管线**（替换压缩编码器/写缓冲策略）：与 Purpur 自身管线耦合、升级易碎；如采用必须单列「收益/风险/回滚」并可一键关闭。
- **禁止**任何引入新端口或新连接的方案。

## 2.0.3 关键洞察

1. **高频小包是主要浪费源**：玩家状态/UI 遥测每条仅几十字节，但每条独占一个包，协议头 + 通道标识的摊薄成本极高 → L1 **合包**是最大杠杆。
2. **字符串键是隐性浪费**：任务 id、经济类型等重复字符串反复传输 → L2 **双端共享字典**收益显著且版本可控。
3. **整对象重发是无效字节源** → L3 **delta + 脏位图**。
4. **原版已压缩** → L4 不盲目二次压缩，避免「压缩已压缩数据」。
